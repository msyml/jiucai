# 2026-08-18 工作日志

## 韭菜地图 · A股知识库 项目搭建

### 项目概述
模仿 https://xiaojiucai.top/ 的功能，在 F:\Code\jiucai 创建了一个 Next.js A股股票知识库网站。
- 技术栈：Next.js 14 + TypeScript + 纯手写CSS
- 数据源：腾讯公开行情API（qt.gtimg.cn）通过 Next.js API 路由代理
- 视觉风格：参考原站但创新——深翠绿底色 + 毛玻璃 + 微动效

### 核心功能
1. 三栏布局：侧边栏（行业标签筛选）+ 主内容区 + 详情滑出面板
2. 全局搜索（代码/名称/行业/笔记），`/`快捷键
3. 行业标签多选组合筛选（31个申万一级行业）
4. 板块筛选（沪市/深市/创业板/科创板/北交所/ST）
5. 排序（涨跌/名称/代码）
6. 重点观察区（止损/支撑/压力位）
7. 价格预警（接近目标价自动触发Toast通知）
8. 股票详情面板（10+项行情数据）
9. 行情每30秒自动刷新
10. 144只代表性A股预置数据

### 关键技术点
- 腾讯API返回GBK编码，需用 `TextDecoder('gbk')` 解码
- 腾讯API字段位置：field 29为空，后续字段全部+1偏移
- field 30=日期时间, 31=涨跌额, 32=涨跌幅, 33=最高, 34=最低
- field 37=成交额(万), 38=换手率, 39=PE, 43=振幅, 44=总市值(亿), 45=流通市值(亿), 46=PB
- 涨跌色按中国惯例：涨红跌绿
- 构建时需先关闭dev服务器，否则 .next 目录被锁导致构建失败

## 数据可编辑化改造（增删改 + 笔记）

用户希望在前端直接增删改股票数据并写笔记。采用方案 A：本地 JSON + API 路由。

### 架构变化
- 新增 `src/lib/store.ts`：以 `stockData.ts` 为种子，首次调用 `/api/data` 时生成 `data/stocks.json`，之后所有读写落盘到该文件。提供 `loadData/saveData/getMarket`。
- 数据不再编译进前端，改为运行时 `fetch('/api/data')` 获取（原 `STOCKS/SECTORS/WATCHLIST/PRICE_ALERTS/STOCK_MAP/getStockCountBySector` 静态导入全部移除，page.tsx 内用同名 alias 接管）。
- 行情 API（`/api/quote`、`/api/search`）也改为读 store，新增股票也能出行情。

### 新增 API 路由
- `GET /api/data`：返回全量快照（含各行业股票计数）
- `POST /api/data/stocks`：新增股票
- `PUT /api/data/stocks/[code]`：编辑（名称/行业/笔记）
- `DELETE /api/data/stocks/[code]`：删除，并级联移除其观察与预警
- `POST/DELETE /api/data/watchlist`：重点观察增删（DELETE 用 `?code=`）
- `POST/DELETE /api/data/alerts`：价格预警增删

### 前端新增 UI
- 工具栏「新增股票」按钮 → 弹窗（代码/名称/行业/笔记）
- 股票卡片 hover 出现「编辑」「删除」按钮
- 详情面板「编辑资料 / 加入观察 / 加入预警」操作
- 重点观察、价格预警卡片右上角「×」移除
- 笔记字段之前已有展示/搜索/筛选，现可通过弹窗写入

### 验证
- `npm run build` 通过（类型检查 OK）
- 端到端 curl 测试：新增→编辑笔记→加入观察/预警→删除(级联清理) 全部成功，股票数回到 144
- 数据持久化在 `data/stocks.json`（用户编辑的真相源，建议备份/纳入版本管理）

### 注意事项 / 踩坑（已修正）
- ⚠️ 重要修正：端口 3120 的旧 dev 进程（PID 3360）实际处于**损坏状态**，并非"热重载了新代码功能正常"。它返回的首页 HTML 为空、CSS 加载不出，导致用户看到"图标特别大 + 布局像乱码"——本质是**整页无样式**：所有 SVG 无 width/height，全靠 CSS 约束，CSS 失效即撑满容器。启动新实例时的 EADDRINUSE 日志**不可忽略**（说明新实例没起起来）。
- 排查手法（已验证）：`curl -s -o <file> http://localhost:3120/`（不要用 `-w size_download`，此环境会误报 0）；再 `curl .../_next/static/css/app/layout.css` 看 CSS 是否 200 且 size>0；`netstat -ano | grep :3120` 找占用端口的 PID。
- 修复手法：`taskkill //F //PID <pid>` 或 PowerShell `Stop-Process -Id <pid> -Force` 杀僵尸进程 → `rm -rf .next` → 重新 `npm run dev`。重启后页面(10KB)与CSS(34KB)均正常。
- 用户端若仍显示坏页面：浏览器可能缓存了损坏的 CSS，需**硬刷新**（Ctrl/Cmd+Shift+R）或开隐私窗口。

## 管理员口令鉴权（只读浏览 / 仅自己可编辑）

用户要求部署后只有自己能改、访客只能看。采用管理员口令方案（改动最小、单仓库内搞定、无需数据库）。

### 实现
- 新增 `src/lib/auth.ts`：`getAdminToken()` 读 `process.env.ADMIN_TOKEN`（未设回退默认 `jiucai-admin` 并 warn）；`requireAdmin(req)` 校验 `Authorization: Bearer <token>`，不符返回 403。
- 新增 `src/app/api/admin/login/route.ts`：POST 校验口令。
- 写路由 `POST/PUT/DELETE /api/data/stocks`、`/api/data/stocks/[code]`、`/api/data/watchlist`、`/api/data/alerts` 开头加 `requireAdmin` 拦截；只读 `GET /api/data`、`/api/quote`、`/api/search` 保持公开。
- 前端 `page.tsx`：`isAdmin` state + `localStorage` 持久化；顶栏「管理登录」按钮 → 登录弹窗（口令）；登录后编辑按钮（新增/卡片编辑删除/详情操作/移除观察预警）才可见；写操作 `authFetch` 自动带 `Authorization` 头。
- `globals.css` 加 `.admin-badge`/`.login-error` 样式；`.env.local` 存 `ADMIN_TOKEN=jiucai-admin`（已被 `.gitignore` 忽略）；新建 `.gitignore`（忽略 `.env*`/`.next`/`node_modules`，保留 `data/`）。

### 验证
- `npm run build` 通过（类型检查 OK）。
- curl 端到端：无 token/错 token 写→403，正确登录→ok，带 token 增删（级联）→ok，公开读→200。
- 访客 SSR 不含「新增股票」按钮、含「管理登录」入口。

### 部署提醒（已告知用户）
- 生产务必 `npm run build && npm start`，勿用 `next dev`。
- **部署前改 `.env.local` 的 ADMIN_TOKEN 为强口令并重启服务**。
- 数据写 `data/stocks.json`：自有 VPS 没问题；Docker 须挂 volume；Vercel/Serverless 无持久盘须换数据库（Postgres/Supabase）。
- 当前 dev 运行于 http://localhost:3120，默认口令 `jiucai-admin`。
